# Model and Rule Catalog

首期“模型”更多是可解释的规则组件，不等于机器学习模型。

| 组件 | 输入 | 输出 | 首期实现 | 升级条件 |
|---|---|---|---|---|
| 每日画像 | 主体、事件、订单、权益、任务 | 日期快照 | SQL 聚合 | 不需要升级 |
| 价值分层 | 历史贡献、频次、组织信号 | S/A/B/C | 分群分位数+规则 | 稳定标签后可评估排序模型 |
| 生命周期 | 最近行为、个人基线、同群基线 | 活跃/风险/沉默/流失 | 角色×产品参数 | 有充足历史后评估生存模型 |
| 复购机会 | 历史付费、近期使用、可用量 | 复购候选 | 可解释规则 | 有真实标签后评估倾向模型 |
| 重点账户 | 组织关系、团队信号、跨产品使用 | 人工核验候选 | 规则+人工核验 | 不建议完全自动化 |
| 决策辅助 | 冻结证据、规则、知识库 | 解释、建议、草稿 | LLM 受治理生成 | 以事实一致率评估 |
| 复盘归因 | 任务、实验组、结果事件 | 增量与原因 | 统计分析 | 保持可审计 |

## 模型上线最低要求

- 标签由业务事件定义，而非由模型自我生成；
- 训练、验证和测试按时间切分；
- 报告 AUC 之外，还要报告校准、覆盖率、召回、成本和分群差异；
- 与规则基线做同一快照的影子比较；
- 有明确的拒绝条件、人工复核和回退路径；
- 模型版本与特征版本进入审计日志。
